# sec-check — หลักสูตรเรียนรู้ "เจาะ → ป้องกัน" (พื้นฐาน → ขั้นสูง)

เอกสารสอนสั้นๆ ต่อเทคนิค · ไว้เป็นความรู้ในตัวเครื่องมือ + ทยอยขึ้นหน้าเว็บทีละอัน
ทุกบทมี 4 ส่วน: **คืออะไร · เจาะยังไง · ทดสอบด้วย sec-check · ป้องกัน**

> ⚖️ ทดสอบเฉพาะระบบของตัวเองหรือที่ได้รับอนุญาตเท่านั้น · เป้าหมายคือหาจุดอ่อนแล้วอุด ไม่ใช่ไปเจาะของคนอื่น

---

## 🟢 Level 1 — พื้นฐาน (ของเปิดโล่ง เจอบ่อยสุด)

### 1.1 บริการไม่ล็อกอิน (No-auth services)
- **คืออะไร:** บริการที่เปิดให้ใครก็เข้าถึงโดยไม่ต้องรหัส เช่น VNC ไม่มีรหัส, Redis, Docker API, MongoDB, RTSP กล้อง
- **เจาะยังไง:** แค่ต่อเข้าไปตรงๆ ก็ควบคุม/อ่านข้อมูลได้ทันที — บอทสแกนเจอแล้วยึดเครื่องไปขุดเหรียญ
- **ทดสอบ:** `seccheck.py lan --level 1` → จับ VNC security type 1, Redis `PING→PONG`, Docker `/version`, RTSP ตอบไม่ถามรหัส
- **ป้องกัน:** ตั้งรหัส/ปิดการเข้าถึงจากภายนอก · bind `127.0.0.1` · ใช้ firewall

### 1.2 รหัสเริ่มต้น (Default credentials)
- **คืออะไร:** อุปกรณ์ที่ยังใช้รหัสโรงงาน เช่น admin/admin, root/root
- **เจาะยังไง:** ลองรหัสยอดนิยมไม่กี่คู่ก็เข้าได้ — มีลิสต์รหัสเริ่มต้นของทุกยี่ห้อบนเน็ต
- **ทดสอบ:** `--default-creds` (เฉพาะ allow-list, ลองเบาๆ หยุดเมื่อเจอ)
- **ป้องกัน:** เปลี่ยนรหัสทุกตัวตั้งแต่แกะกล่อง · รหัสยาว ไม่ซ้ำ

### 1.3 ส่งข้อมูลไม่เข้ารหัส (Cleartext protocols)
- **คืออะไร:** telnet, FTP, HTTP, SNMP v1/v2c — ส่งรหัส/ข้อมูลเป็นข้อความเปล่า
- **เจาะยังไง:** ดักฟังในวงเดียวกัน (sniffing) เห็นรหัสตรงๆ · HTTP Basic auth = base64 ถอดได้ทันที
- **ทดสอบ:** sec-check จับพอร์ต 23/21, Basic-auth-over-http, SNMP community `public`
- **ป้องกัน:** ใช้ SSH แทน telnet, FTPS/SFTP, HTTPS, SNMPv3

### 1.4 ไฟล์/หน้าโผล่ (Exposed files & listing)
- **คืออะไร:** directory listing เปิด, `.git/`, `.env`, backup, หน้า admin ไม่ป้องกัน
- **เจาะยังไง:** เดา path ตรงๆ หรือใช้ wordlist (gobuster/ffuf) หาไฟล์ที่ไม่ควรเปิด
- **ทดสอบ:** โมดูล web ตรวจ directory listing, path ยอดฮิต, security headers
- **ป้องกัน:** ปิด listing · กันไฟล์ dot-file · ใส่ auth หน้า admin

## 🟡 Level 2 — โปรโตคอล/การตั้งค่าที่อ่อน

### 2.1 SMB รุ่นเก่า (SMBv1)
- **คืออะไร:** โปรโตคอลแชร์ไฟล์ Windows รุ่นเก่า มีช่องโหว่ร้ายแรง
- **เจาะยังไง:** EternalBlue (MS17-010) ยึดเครื่องได้โดยไม่ต้องรหัส — เป็นช่องที่ WannaCry ใช้
- **ทดสอบ:** ตรวจว่าเปิด SMBv1 / ไม่บังคับ signing
- **ป้องกัน:** ปิด SMBv1, เปิด SMB signing, อัปเดต Windows

### 2.2 WiFi อ่อน (WEP / WPS)
- **คืออะไร:** WEP = เข้ารหัสที่แตกได้ในไม่กี่นาที · WPS = PIN 8 หลักเดาได้
- **เจาะยังไง:** WEP จับ IV แล้วถอด · WPS brute PIN (Reaver) ได้รหัส WiFi
- **ทดสอบ:** WiFi module Tier-1 — จับ WEP/WPA1, WPS เปิด, PMF ปิด
- **ป้องกัน:** ใช้ WPA2/WPA3, ปิด WPS, เปิด PMF, รหัสยาว ≥ 14 ตัว

### 2.3 TLS/SSL อ่อน
- **คืออะไร:** TLS 1.0/1.1, cipher อ่อน, cert หมดอายุ/self-signed
- **เจาะยังไง:** ลดระดับการเชื่อมต่อ (downgrade) แล้วดักอ่าน (MITM)
- **ทดสอบ:** TLS module — เวอร์ชัน, cipher, cert, HSTS
- **ป้องกัน:** TLS 1.2+ เท่านั้น, cipher แข็ง, ต่ออายุ cert, เปิด HSTS

## 🟠 Level 3 — เวอร์ชันเก่า / ช่องโหว่ที่รู้จัก (CVE)

### 3.1 จับเวอร์ชัน → CVE
- **คืออะไร:** บริการที่โชว์เวอร์ชันเก่า (เช่น `thttpd/2.27 2015`, Apache/OpenSSH เก่า)
- **เจาะยังไง:** หา exploit สำเร็จรูปของเวอร์ชันนั้น (Exploit-DB/Metasploit) ยิงได้เลย
- **ทดสอบ:** cve module — อ่าน banner แล้วจับคู่ฐานช่องโหว่ที่รู้จัก
- **ป้องกัน:** อัปเดตเฟิร์มแวร์/แพ็กเกจ · ซ่อน banner เวอร์ชัน

### 3.2 เราเตอร์เฟิร์มแวร์เก่า
- **คืออะไร:** router รุ่นเก่าไม่อัปเดต มี CVE command-injection / auth-bypass
- **เจาะยังไง:** ส่ง request พิเศษข้ามล็อกอิน หรือสั่งรันคำสั่งบน router
- **ทดสอบ:** router module — เวอร์ชัน, พอร์ตที่ไม่ควรเปิด (SMB/telnet/remote mgmt), UPnP
- **ป้องกัน:** อัปเฟิร์มแวร์, ปิด remote management/WAN admin, ปิด UPnP ถ้าไม่ใช้

## 🔴 Level 4 — เว็บแอป / ตั้งค่าพลาด

### 4.1 SQL Injection
- **คืออะไร:** ใส่คำสั่ง SQL ผ่านช่องกรอก ทำให้ดึง/แก้ฐานข้อมูลได้
- **เจาะยังไง:** ใส่ `' OR '1'='1` หรือ payload ดึงตาราง (ฝึกบน DVWA)
- **ทดสอบ:** webapp module (บนเป้าฝึก) — ลอง payload ปลอดภัยดูอาการ
- **ป้องกัน:** ใช้ parameterized query / prepared statement · ไม่ต่อสตริง SQL เอง

### 4.2 XSS (Cross-Site Scripting)
- **คืออะไร:** ฝัง JavaScript ในหน้าเว็บ ทำงานบนเบราว์เซอร์เหยื่อ (ขโมย cookie)
- **เจาะยังไง:** ใส่ `<script>...</script>` ในช่องที่เว็บเอาไปแสดงดิบ
- **ทดสอบ:** ตรวจว่า input ถูก encode ก่อนแสดงไหม (บนเป้าฝึก)
- **ป้องกัน:** escape/encode output · ตั้ง Content-Security-Policy

### 4.3 IDOR / Path Traversal / SSRF
- **คืออะไร:** เข้าถึงของคนอื่นด้วยการเปลี่ยน id, อ่านไฟล์ระบบด้วย `../`, หลอกเซิร์ฟเวอร์ยิง request ภายใน
- **เจาะยังไง:** แก้พารามิเตอร์ใน URL/request
- **ทดสอบ:** webapp module (เป้าฝึก) — ลองเปลี่ยน id/path ดูว่ากันไหม
- **ป้องกัน:** เช็กสิทธิ์ทุก request · validate path/URL · allow-list ปลายทาง

### 4.4 RDP/SSH ตั้งค่าหละหลวม
- **คืออะไร:** RDP ไม่เปิด NLA, SSH ยอม root/รหัสผ่าน
- **เจาะยังไง:** เดารหัส (brute) หรือใช้ช่องโหว่ RDP เข้าเครื่อง
- **ทดสอบ:** host/windows module — NLA, root login, password auth
- **ป้องกัน:** SSH key-only ปิด root · RDP เปิด NLA + จำกัด IP · เปิด 2FA

## ⚫ Level 5 — ขั้นสูง (เฉพาะ lab / เครือข่ายตัวเอง)

### 5.1 เจาะรหัส WiFi ตัวเอง (passphrase strength)
- **คืออะไร:** ทดสอบว่ารหัส WiFi ของเรา "เดาได้" ไหม
- **เจาะยังไง:** จับ WPA handshake ของ SSID ตัวเอง → เทียบ wordlist (aircrack-ng/hashcat)
- **ทดสอบ:** WiFi Tier-2 `--wifi-crack` (ต้อง root + การ์ด monitor mode · รันในเทอร์มินัลเอง · เฉพาะ SSID ที่ยืนยันเป็นเจ้าของ)
- **ป้องกัน:** รหัสยาว ≥ 14–20 ตัว สุ่ม ไม่ใช่คำในดิกชันนารี · WPA3

### 5.2 ต่อช่องโหว่ + ยกสิทธิ์ (chaining / privesc)
- **คืออะไร:** เอาช่องเล็กๆ หลายอันมาต่อกันจนยึดเครื่อง แล้วไต่เป็น root/admin
- **เจาะยังไง:** เข้าได้สิทธิ์ต่ำ → หา SUID/บริการตั้งค่าผิด/เวอร์ชัน kernel เก่า → ยกสิทธิ์ (ฝึกบน Metasploitable)
- **ทดสอบ:** host module จับ SUID/world-writable/sudo misconfig เป็นสัญญาณ privesc
- **ป้องกัน:** ลดสิทธิ์เท่าที่จำเป็น · อัปเดต kernel · ตรวจ SUID เป็นประจำ
