# sec-check — ดีไซน์ระบบ (Design Doc)

เครื่องมือ **ทดลองเจาะระบบเพื่อเรียนรู้แล้วอุดช่องโหว่** (offensive เพื่อ defensive)
เริ่มจากอุปกรณ์ในบ้านของตัวเอง ขยายไปใช้ในองค์กรได้ · ใช้ง่าย · ฝั่ง Python

> **หลักการสำคัญ:** ทดสอบเฉพาะระบบที่เป็นเจ้าของหรือได้รับอนุญาตเป็นลายลักษณ์อักษรเท่านั้น ·
> ค่าเริ่มต้นไม่ทำลาย (non-destructive) · ทุกอย่างมี audit log · เป็นเครื่องมือเพื่อการป้องกัน

---

## 1. เป้าหมาย

1. **เรียนรู้แบบลงมือจริง** — เห็นว่า "ยังเจาะได้" 🔴 → ปรับแก้ → รันซ้ำจน "เจาะไม่ได้" 🟢
2. **ใช้ป้องกันจริง** — บ้าน แล้วต่อยอดไปออฟฟิศ/องค์กร
3. **ใช้ง่าย** — ลง repo → สแกนบ้านได้เลย → เห็นผลเป็นหน้าเว็บสวยๆ + แผนที่เครือข่าย
4. **ให้ AI เรียกได้** — มี REST API และ MCP server คนที่ชอบใช้ AI สั่งได้โดยไม่ต้องกดเอง แต่ยังเห็นหน้าผลสวยๆ

## 2. Stack (เลือกให้ใช้ง่ายที่สุด)

| ชั้น | เลือกใช้ | เหตุผล |
|---|---|---|
| ภาษา | **Python 3.10+** | ตรงกับ disk-check · ข้ามเครื่องง่าย |
| แกนหลัก | **stdlib ล้วน** (socket, http.server, sqlite3, ssl, asyncio) | ไม่ต้อง `pip install` ก็รันได้ |
| เครื่องมือเสริม (ถ้ามี) | nmap, nikto, nuclei, sslscan, testssl | ห่อไว้ ใช้เมื่อมีติดตั้ง ไม่มีก็ยังทำงานได้ |
| หน้าเว็บ | **เสิร์ฟจาก Python เอง** (http.server) + HTML/CSS/JS ล้วน ไม่มี build step | เปิดใช้ทันที เหมือน disk-check web |
| ฐานข้อมูล | **SQLite** (`data/seccheck.db`) | เก็บเป้าหมาย/สแกน/ผล + ประวัติก่อน-หลัง |
| i18n | `i18n.py` + `locales/*.json` (ไทย/อังกฤษ) | ยกแนวจาก disk-check |
| แพ็กเกจ | รันตรง `./scan.sh` · หรือ `pipx install .` · หรือ Docker (สำหรับองค์กร) | ติดตั้งง่ายทุกแบบ |

**ไม่เลือก** framework หนักๆ (Django/React/Node) — ตั้งใจให้ลงแล้วรันได้เลย ไม่ต้องตั้ง environment

## 4. ระบบโมดูลเช็ก (หัวใจ — เพิ่มได้เรื่อยๆ)

ทุกเช็กหน้าตาเหมือนกัน (interface เดียว) เพิ่มของใหม่แค่หยอดไฟล์ในโฟลเดอร์ `checks/`

```python
class Check:
    id = "ssh.password_auth"        # รหัสเฉพาะ
    category = "linux"              # หมวด (ใช้จัดกลุ่ม/เลือกใน UI)
    level = 1                       # ระดับความยาก 1–5
    title = "SSH ยอมล็อกอินด้วยรหัสผ่าน"
    needs_root = False
    def applies(self, target) -> bool: ...     # เป้านี้เข้าข่ายไหม (เปิดพอร์ต 22?)
    def run(self, target) -> Finding: ...       # ทดสอบแบบไม่ทำลาย
```

**ผลลัพธ์ (Finding)** — เก็บลง DB และโชว์เหมือนกันทุกเช็ก:

| ฟิลด์ | ความหมาย |
|---|---|
| `state` | 🔴 `VULNERABLE` / 🟢 `SECURE` / ⚪ `INFO` / ❓ `UNKNOWN` |
| `severity` | critical / high / medium / low / info |
| `evidence` | สิ่งที่เจอ (เช่น banner, response) ไว้ยืนยัน |
| `what` / `why` / `fix` | คืออะไร · เสี่ยงยังไง · แก้ยังไง (ไทย+อังกฤษ) |
| `refs` | ลิงก์ CVE / คู่มือ |
| `rerun_hint` | รันซ้ำยังไงเพื่อยืนยันว่าแก้แล้ว |

**ระดับความยาก (เลือกได้ใน UI/CLI):**

| Level | เก็บอะไร | ตัวอย่าง |
|---|---|---|
| 1 ง่าย | ของเปิดโล่ง | พอร์ตเปิดเกิน, รหัสเริ่มต้น, หน้า admin ไม่ล็อกอิน, RTSP เปิด |
| 2 | โปรโตคอลอ่อน | SMBv1, Basic auth over http, telnet, TLS เก่า |
| 3 | เวอร์ชัน/CVE | จับคู่ banner ↔ ช่องโหว่ที่รู้จัก |
| 4 | ตั้งค่าพลาด | RDP ไม่มี NLA, SSH root login, share เปิด |
| 5 ยาก | ยืนยันเจาะได้ (บนเป้าฝึก) | SQLi/XSS บน DVWA/Juice Shop |

**8 หมวด (แยกไฟล์โมดูล เพิ่มทีละเฟส):**
`network` · `router` · `camera` · `windows` · `linux` · `mac` · `webapp` · `mobile/iot`

## 5. หน้าเว็บ (ตามลำดับที่ผู้ใช้เจอ)

1. **Dashboard** — สรุปรวม: เจอกี่อุปกรณ์ · กี่ช่องโหว่แยกตามระดับ · เทรนด์ว่าดีขึ้นไหม (ก่อน/หลัง) · ปุ่ม "สแกนเลย"
2. **Scan (สั่งสแกน)** — เลือกเป้า (จาก allow-list) · เลือกหมวด/ระดับ · กด Scan · เห็น progress สด · 🔴/🟢 ขึ้นทีละอัน
3. **Network Map (แผนที่บ้าน)** — เหมือนตัวอย่างที่ทำให้ดู: อุปกรณ์รอบเราเตอร์ สีตามความเสี่ยง แตะดูรายละเอียด
4. **Findings (รายการช่องโหว่)** — กรอง/เรียงตามความรุนแรง · แต่ละอันกางดู what/why/fix · ปุ่ม "รันซ้ำยืนยันแก้แล้ว"
5. **Target detail (รายอุปกรณ์)** — พอร์ต · บริการ · ช่องโหว่ · ประวัติสแกน (เทียบก่อน/หลัง) · โน้ต
6. **Settings (ตั้งค่า)** — ภาษา(ไทย/อังกฤษ) · ระดับ/หมวดเริ่มต้น · ความเร็ว/จังหวะสแกน · เปิด-ปิดการลองรหัสเริ่มต้น · คีย์ API · เปิด MCP · PIN เข้าเว็บ
7. **Targets / Allow-list** — ระบุวง/IP ที่ "เป็นเจ้าของ/ได้รับอนุญาต" + ติ๊กยืนยันก่อนสแกนครั้งแรก (กันสแกนผิดที่)
8. **History / Compare** — ไทม์ไลน์: ครั้งนี้เทียบครั้งก่อน อันไหนแก้แล้ว 🟢 อันไหนโผล่ใหม่ 🔴
9. **Report** — ออกเป็น HTML/PDF/JSON สวยๆ สำหรับส่งหัวหน้า/ลูกค้า (ไทย/อังกฤษ)

สไตล์: โทนมืด การ์ด สีตามความเสี่ยง มือถือใช้ได้ — มาตรฐานเดียวกับ disk-check

## 6. REST API (ให้สคริปต์/ระบบอื่นเรียก)

```
GET  /api/targets                 รายการเป้าใน allow-list
POST /api/scan   {targets,categories,level}   เริ่มสแกน → คืน scan_id
GET  /api/scan/<id>               สถานะ + ผลสด
GET  /api/findings?severity=high  รายการช่องโหว่
GET  /api/target/<ip>             รายละเอียด + ประวัติ
GET  /api/report/<scan_id>.json   รายงานเครื่องอ่าน (ให้ AI อ่านง่าย)
GET  /api/map                     ข้อมูลแผนที่เครือข่าย
```
ป้องกันด้วย API key (ตั้งใน Settings) · อ่านอย่างเดียวเป็นค่าเริ่มต้น · สแกนต้องเป้าอยู่ใน allow-list

## 7. MCP server (ให้ AI อย่าง Claude สั่งได้เลย)

รัน `seccheck.py --mcp` เปิดเป็น MCP server · AI เรียก tool เหล่านี้ได้ (คนไม่ต้องกด แต่ยังเปิดหน้าเว็บดูผลสวยๆ ได้):

| MCP tool | ทำอะไร |
|---|---|
| `list_targets` | ดูเป้าที่อนุญาต |
| `scan` | สั่งสแกน (เฉพาะเป้าใน allow-list) |
| `get_findings` | ดึงช่องโหว่ที่เจอ (JSON) |
| `explain_finding` | อธิบายช่องโหว่ + วิธีแก้ |
| `get_report` | ดึงรายงาน |
| `compare_scans` | เทียบก่อน/หลังแก้ |

> MCP/API **ไม่ข้าม allow-list และ non-destructive** — AI สั่งได้เท่าที่คนตั้งกรอบไว้

## 8. Data model (SQLite)

- `targets(id, label, ip/cidr, owner_confirmed, authorized_note, added_at)`
- `scans(id, started_at, level, categories, mode)`
- `findings(id, scan_id, target, check_id, state, severity, evidence, note)`
- เทียบก่อน/หลัง = query `findings` ของ target เดียวกันข้าม scan → โชว์ 🔴→🟢

ข้อมูลจริง (ผลสแกน/allow-list/คีย์) **ไม่ขึ้น git** (`.gitignore`)

## 9. ความปลอดภัย / การขออนุญาต (สำคัญ เพราะให้องค์กรเอาไปใช้)

- **Allow-list บังคับ** — สแกนได้เฉพาะวง RFC1918/เป้าที่ติ๊กยืนยันว่าเป็นเจ้าของ/ได้รับอนุญาต
- **ยืนยันก่อนสแกนครั้งแรก** ของแต่ละเป้า + เก็บหมายเหตุการอนุญาต
- **Non-destructive เป็นค่าเริ่มต้น** · การลองรหัสเริ่มต้นจำกัดจำนวน/มีจังหวะ ปิดได้
- **ไม่มีโมดูลทำลาย/DoS/แพร่กระจาย** · การยืนยันเจาะจริง (เช่น SQLi) จำกัดไว้กับเป้าฝึก
- **Audit log** ทุกการสแกน (ใคร/เมื่อ/เป้าไหน) · **หน้าแรกมีคำเตือนทางกฎหมาย** ให้ทดสอบเฉพาะระบบที่ได้รับอนุญาต

## 10. แพ็กเกจให้องค์กรใช้

- `pipx install .` หรือ `docker run 6amdev/sec-check` → เปิดเว็บที่ LAN
- ตั้ง allow-list ต่อองค์กร · รายงานมีโลโก้/ชื่อองค์กรได้ · ส่งออก PDF
- โหมดอ่านอย่างเดียวสำหรับผู้ชมรายงาน · คนตั้งค่า/สั่งสแกนต้องมี PIN/คีย์
